# OpenVLA-4L 四种微调与过程证据设计

## 目标

在单张 NVIDIA GeForce RTX 3090 24GB 和 32GB 主机内存上，使用本项目真实五次水杯示教数据，完成 Full Fine-tuning、LoRA（rank=32）、Last-Layer-Only 和 Frozen-Vision 四种微调实验。四种方法必须使用同一个缩减规模 OpenVLA 模型、相同数据划分和相同闭环评测协议；不得以另一种参数高效方法冒充 Full Fine-tuning 或 Frozen-Vision。

## 统一模型

从 `models/openvla-7b` 本地权重构建 `OpenVLA-4L`：

- 保留原始双视觉编码器、视觉—语言投影器、词嵌入、动作词表和动作解码接口。
- 语言模型由32个 Transformer 层缩减为4层，以降低可训练参数和优化器状态。
- 四种方法均从同一份 `OpenVLA-4L` 初始检查点开始，保证资源和成功率比较具有可比性。
- 报告中始终写明这是“项目适配的 OpenVLA-4L”，不得将其参数量或结果表述成完整 OpenVLA-7B。

## 四种方法

1. **Full Fine-tuning**：训练 OpenVLA-4L 的全部参数。
2. **LoRA（rank=32）**：冻结基础参数，对所有线性层注入 rank=32、alpha=64 的 LoRA。
3. **Last-Layer-Only**：仅训练第4个语言 Transformer 层和语言模型输出头，生成独立检查点。
4. **Frozen-Vision**：冻结双视觉编码器，训练投影器、4层语言模型和动作输出相关参数。

每种方法都必须真实执行优化器更新、保存检查点、训练日志、资源记录和可审计元数据。

## 数据和训练协议

- 数据集：`datasets/water_cup_expert`。
- 五次示教：seed 0、1、2、3、5。
- 训练数据从五条轨迹中抽取图像—动作对，固定随机种子。
- 物理 batch size 为1；默认梯度累积16次，有效 batch size 为16。
- 如果 Full Fine-tuning 或 Frozen-Vision 仍接近显存上限，允许启用梯度检查点、BF16、8-bit 优化器或将梯度累积拆分到CPU保存，但不能减少该方法定义中的可训练参数。
- 首先运行短程可训练性探测，再运行正式训练；正式步数根据损失收敛和闭环小样本调优决定，所有调参尝试保留记录。

## 闭环评测

- 不涉及真实机械臂。
- 优先使用本项目水杯抓取放置仿真环境，对每个独立检查点执行相同初始种子和相同最大步数的纯策略闭环评测。
- 禁止专家恢复、轨迹回放替代策略动作或按结果人工修改成功标记。
- 如果缩减模型与现有仿真动作解码接口不兼容，先以测试固定接口，再修复模型保存和加载流程。
- 每种方法至少保留逐回合成功布尔值；成功率只由真实成功回合数除以总回合数得到。

## 过程证据

每种方法保存以下真实过程证据：

1. 训练控制台截图：实验ID、方法、检查点、step、loss、学习率和时间。
2. GPU资源截图：训练进程运行期间的 `nvidia-smi`，包含GPU型号、显存占用和进程。
3. 仿真过程截图：至少包含初始、接近/抓取、搬运/放置和最终状态关键帧；图上标注方法、任务、回合、步数和成功状态。
4. 原始日志、JSON报告与图片路径相互引用，能够从最终表格回溯到训练和评测证据。

截图必须来自实际运行，不用绘制的示意图或汇总柱状图冒充实验过程。

## 实现边界

- 新建独立的缩减模型构建、统一训练、评测证据采集和4.6.1汇总脚本。
- 不覆盖现有 OpenVLA-7B、LoRA 检查点或历史实验结果。
- 所有输出写入 `outputs/experiment_4_6/openvla_4l/`，检查点写入 `models/experiment_4_6_openvla_4l/`。
- 遇到OOM时先降低临时张量、启用检查点或更换优化器；不得静默改变方法定义。
- 三次修复后仍重复出现同一阻断问题时才向用户汇报。

## 验证标准

- 四种训练运行均以退出码0结束且至少完成一次真实参数更新。
- 四个独立检查点均可重新加载并输出7维动作。
- Last-Layer-Only检查点存在，元数据证明仅最后语言层和输出头发生训练。
- 四种方法均生成训练日志、GPU证据图和闭环关键帧。
- 汇总程序从原始JSON计算参数量、峰值显存和成功率，不手工填写实验数字。
- 最终在对话中输出完整4.6.1正文、表格和实验过程图片。
