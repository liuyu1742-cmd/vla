# VLA82 中期 8 类任务与 60 物体补测设计

## 1. 目标

在不引入真实机械臂的前提下，使用公开真实人体操作视频和 RoboCasa 仿真平台补齐中期测试证据：8 类家政任务均完成示范动作解析、技能学习和仿真复现；从既定 VLA82 范围选出的 60 种物体均完成对应抓取、清洁或设备控制操作，并为每项保存视频、首末帧、识别结果和机器可读报告。

本设计采用混合式视觉模仿学习链路。它不宣称为纯 OpenVLA 端到端自主控制，也不把环境重置、动作接口冒烟测试或官方动作回放单独计为完整操作成功。

## 2. 已确认的验收边界

- 人体示范允许使用 EPIC 等公开真实人体操作视频，不要求现场重新拍摄。
- 仅验证仿真机器人，不接入真实机械臂。
- 测试对象必须来自既定 VLA82 表格范围和已确定的 60 项选择，不从 `C:\RobotProject` 任务清单另行选取。
- 8 类任务和 60 种物体均逐项判定；只有实际证据满足门槛的项目才计为通过。
- 同一问题失败三次后进行全面排查，保留诊断记录并继续修复；不因第三次失败自动停止整个测试。
- 不将功能代理物体直接写成真实目标物体通过。没有 RoboCasa 原生模型时，创建保留目标类别、尺寸和关键可供性的简化数字孪生，并在报告中标注资产来源和建模方式。

## 3. 方案选择

采用“公开人体视频 + Skill IR 技能学习插件 + OpenVLA 视觉识别/动作意图 + RoboCasa 受监督执行”的混合方案。

未采用纯 OpenVLA 全自主闭环作为唯一验收路径，因为现有 8 类纯闭环运行已经产生完整轨迹，但成功数为 0/8，直接扩展到 60 物体无法快速、可靠地达到验收门槛。未采用单纯官方动作回放，因为它缺少从人体示范到技能学习产物的可审计绑定。

## 4. 系统组成

### 4.1 示范材料化

为 8 类任务各选择至少一段语义匹配的公开真实人体操作视频。材料化过程保存：数据集名称、视频或片段 ID、原始路径、时间范围、文件大小、SHA-256、解码状态和代表帧。公开视频只作为视觉示范输入，不被描述为本项目现场采集。

### 4.2 视觉解析与 Skill IR

示范解析器从视频提取目标物体、手部或人体关键点、手—物接触、对象运动和阶段边界。每类任务生成一个经过 Schema 校验的 Skill IR，阶段至少覆盖：定位、接近、抓取或接触、执行操作、释放或完成。

无法从视觉证据支持的阶段不得由文字标注静默补造。视频解码失败、目标物体不可见、缺少必要接触证据或阶段顺序非法时，该类任务保持失败状态并进入修复流程。

### 4.3 60 物体精确映射

60 项选择沿用现有 VLA82 选择 ID、任务类别、物体名称和操作标签。每项映射到以下一种仿真实体：

1. RoboCasa 原生同类物体；
2. 项目中已有的同类三维资产；
3. 新建的简化数字孪生，保持目标类别、近似尺寸、抓取面、接触面或控制部件等关键可供性。

映射报告必须区分原生资产和简化数字孪生。语义无关的功能代理不得计入 60 物体精确通过数。

### 4.4 OpenVLA 与仿真执行

OpenVLA读取当前仿真视觉帧和由 Skill IR 生成的阶段提示，输出视觉识别结果和动作意图。RoboCasa 受监督执行器负责动作边界、安全恢复和任务成功谓词检查。报告必须记录 OpenVLA 原始输出、最终执行动作、监督器干预次数以及是否使用脚本化或专家动作。

该链路的合格名称为“混合式视觉模仿学习与仿真复现”。任何使用专家动作、状态监督或动作回放的项目不得标为“纯 OpenVLA 自主闭环”。

## 5. 测试矩阵

### 5.1 八类任务

每类任务必须完成：

1. 公开人体示范视频可解码且来源可追溯；
2. 视觉解析产生非空物体、接触或阶段证据；
3. Skill IR 通过 Schema 和阶段顺序校验；
4. Skill IR 成功绑定到一个仿真任务；
5. 仿真执行达到该任务的成功谓词；
6. 操作视频、首帧、末帧、识别结果和报告完整。

### 5.2 六十种物体

每种物体执行一次与表格操作标签一致的抓取、清洁或设备控制操作。每项必须满足：

1. 真实公开数据或仿真视觉帧中的目标类别识别结果与期望类别一致；
2. 加载的是原生同类资产或明确标注的同类数字孪生；
3. 实际执行非空动作轨迹；
4. RoboCasa 成功谓词或等价的可审计状态变化成立；
5. 视频可解码，首末帧存在且不是同一图像；
6. 报告包含选择 ID、任务、物体、操作、随机种子、识别结果、动作来源和最终状态。

## 6. 证据结构

补测证据统一写入：

```text
C:\OpenVLA-Simulator\outputs\midterm_testing_vla82\acceptance_completion_8x60
```

每个项目使用独立目录：

```text
<selection_id>/
  source_demo.json
  source_demo_preview.png
  skill_ir.json
  recognition.json
  rollout.mp4
  first_frame.png
  last_frame.png
  report.json
```

根目录另保存：

```text
manifest.json
acceptance_matrix.xlsx
evidence_contact_sheet.png
failure_diagnostics.json
```

`manifest.json` 是唯一汇总真源。Excel 和汇总图只能从该清单生成，不得手工修改通过数量。

## 7. 合格判定

只有同时满足以下条件，最终状态才允许为 `PASS`：

- 八类任务通过数为 8/8；
- 六十种物体操作通过数为 60/60；
- 六十种物体识别通过数为 60/60；
- 68 个验收项目的必需证据文件均存在并可读取；
- 不存在被计为精确通过的语义无关代理物体；
- 汇总清单中没有 `NOT_EXECUTED`、`TASK_FAILED` 或 `EVIDENCE_INCOMPLETE`。

如果任一条件不满足，报告必须给出实际通过数和失败项，不得将接口冒烟、600 次独立推理或公开动作回放替代完整合格结论。

## 8. 错误处理和恢复

- 视频或图片读取失败：记录路径、解码器和错误，检查源文件后重试。
- 识别失败：保存失败帧、类别分数和阈值；检查类别映射、视角和模型覆盖后再训练或调整数据。
- 环境生成失败：记录随机种子、资产路径和堆栈；优先修复资产或采样配置。
- 操作失败：保存完整轨迹和末帧，区分识别、规划、控制、抓取和成功谓词问题。
- 同一根因连续三次修复仍失败：执行跨数据、模型、动作适配器、仿真资产和判定器的全面排查，更新诊断清单并继续实施可验证修复。

## 9. 验证策略

实现阶段先为清单校验、证据完整性、数字孪生映射、视频解码、识别判定和总体验收门槛编写失败测试，再实现最小功能。长时间补测先运行单项目烟测，再按任务类别分批运行；每批完成后验证文件和清单，避免到最后才发现证据缺失。

最终完成前重新运行全部相关单元测试、证据完整性检查、视频解码检查和 8×60 汇总验收命令。只有最新命令明确返回 8/8、60/60、60/60 且零证据缺失，才报告完全满足中期要求。
