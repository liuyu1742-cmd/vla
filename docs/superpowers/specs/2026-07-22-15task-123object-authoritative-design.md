# 15类任务与123物体视觉技能迁移权威设计

> 状态：已于2026-07-22经用户书面批准。本文以第五章和《家庭服务任务物体数据表.xlsx》为权威输入，取代此前根据需求示例推断的任务/物体范围。

## 1. 项目验收目标

项目的主标准是：

> 基于视觉的人类动作捕获、解析和技能学习迁移技术，使家政服务机器人支持不少于15类典型任务和120类典型物体的操作技能学习。

系统必须形成可追溯闭环：

`人类示范视频 → 人体/手部/物体解析 → 动作与意图 → 结构化技能 → 机器人示教/训练 → 闭环执行 → 反馈与再学习`

不以“是否只用一个端到端大模型”为验收条件。只做视频分类、只输出语言描述、只检测物体、播放固定轨迹或仅在仿真真值下完成任务，均不能单独计为技能迁移成功。

### 2.3 123个唯一物体，而不是138个物体

Excel有138条关系，但按英文 `object` ID去重后有123个唯一候选物体，中文名去重后同样为123个。因此：

- `object_registry` 登记全部123个候选物体并保留Excel来源。
- `task_object_matrix` 将每个服务任务—物体组合标记为直接适用、间接/设备控制、组合资源或不适用。
- 只有至少映射到一个合理服务任务和一个可执行技能的对象，才计为有效操作物体。
- 项目硬验收要求至少120个有效物体通过操作技能验证；若123个候选对象过滤后不足120个，则从第五章技能表补充合理设备、传感器或日用品。
- 同一个物体可属于多个任务组，不能重复计数。

跨任务复用的物体包括 `remote_control`、`robot_vacuum`、`fire_alarm`、`washing_machine`、`air_conditioner`、`refrigerator`、`fan`、`electric_curtain`、`smart_lock`、`television`、`laptop`、`book`、`mobile_phone`、`toy`。其中 `remote_control` 出现在3个任务组，其余出现在2个任务组。

### 2.4 文档中三种“15”必须分开

项目同时存在三套不同的15类概念：

1. 第五章15类服务任务：最终项目验收维度。
2. Excel 15个数据集任务组：数据组织维度。
3. 第三章表3-1的15种动作原语：技能解析与执行维度。

第三章表3-1的动作原语为：握取、捏取、托举、轻放、推入、悬挂、擦拭、拖洗、折叠、堆叠、排列、推送、搬运、旋转、递送。表中“托洗”按上下文归一化为“拖洗”。刷洗、按压、滑动、搅拌、切割、倾倒等作为扩展原语进入后续版本。

## 3. 对源文档内部数量差异的处理

第五章的数量不能直接作为唯一物体数：

- 表5-1的15类技能数量相加为150，表5-2至表5-9的明细数量相加也为150。
- 两处总数相同，但类别分配不一致：家电综合管理为35与40、环境调节为15与20、两类安防合计为20而安防明细为15、物品递送为15与25、整理收纳为10与20。
- 表5-1后六类（能源管理、设施监控、场景联动、健康关怀、娱乐服务、其他综合）合计25项，没有各自独立的明细表，内容与前述设备/监控类技能存在复用。
- 正文使用“120种以上技能”的表述。

这些数字描述的是技能条目，并含跨类别复用，不等于唯一物体数。项目采用以下单一口径消除歧义：

- 服务任务类别：以表5-1的15类名称为准。
- 唯一物体：以Excel英文 `object` ID去重的123个为准。
- 技能实例：以 `task_id + object_id + goal + backend + skill_version` 唯一确定，可超过123。
- 动作原语：以版本化原语注册表管理，不与服务任务数量混算。

## 4. 推荐总体架构

### 4.1 人类视频理解通路

`RGB/RGB-D视频`

→ 人体检测与跟踪

→ 身体/手部关键点

→ 物体检测、分割与跟踪

→ 手—物接触和物体状态变化

→ 时序滤波、动作边界检测与原语分类

→ 意图三元组 `(Action, Object, Goal)`

→ 任务语法图和 `Skill IR`

首版优先使用可部署的预训练模块，而不从零训练文档中的全部研究网络：

- 身体姿态：RTMPose或DWPose类全身关键点模型；精度不足时再升级HRNet+ViT双分支。
- 手部：MediaPipe Hands或等价21点手部模型；遮挡严重时引入多视角。
- 时序稳健：置信度门控、骨骼长度约束、卡尔曼滤波和短时插值。
- 动作识别：骨架时序编码器与RGB/光流特征融合；先做15原语，再扩展精细动作。
- 意图理解：融合动作、目标物体、场景、语言和机器人状态，输出可校验结构，不直接输出自由文本作为执行命令。

### 4.2 三层技能表示

采用文档第四、五章提出的层次化思想，并用统一 `Skill IR` 落地：

1. 任务层：任务语法图/DAG，描述目标、子任务、先后关系、条件分支和完成谓词。
2. 动作层：动作原语序列，描述对象、相对位姿、接触事件、约束和阶段完成条件。
3. 控制层：具体后端的连续动作、设备命令、导航目标或告警动作。

每个Skill IR必须包含：来源视频、任务类别、数据集任务组、对象ID、目标、动作阶段、接触事件、前置条件、成功谓词、失败恢复、后端、置信度和版本。

### 4.3 人体动作到机器人动作的正确桥接

普通人类视频没有机器人7维动作标签，不能直接把骨架坐标当作OpenVLA训练标签。采用以下桥接：

1. 从人体视频提取对象中心的相对运动、接触开闭、关键位姿和阶段边界。
2. 用逆运动学、轨迹优化、约束规划或仿真专家把这些约束转成机器人可执行示教。
3. 用DTW对齐人体节奏与机器人节奏，但不复制绝对速度。
4. 将成功的机器人示教用于OpenVLA LoRA/行为克隆训练。
5. 在线失败状态由安全专家修正并通过DAgger加入训练集。

这种方案保留“从人类视频学习任务和动作结构”，同时避免人体与机械臂形态、坐标系和动力学差异导致不可执行。

### 4.4 机器人策略与执行

当前OpenVLA继续作为视觉闭环机械臂策略基线：

- 输入：当前机器人相机图像、语言目标、Skill IR阶段、必要的机器人状态与短时历史。
- 输出：末端位姿增量、旋转增量和夹爪动作。
- 训练：LoRA/行为克隆初始化，随后加入DAgger恢复样本。
- 执行：动作缩放、边界裁剪、碰撞约束、接触顺序、夹爪保持和失败重试由安全监督器负责。

OpenVLA原始离散自回归动作在高频、多步和精细接触任务中存在限制。连续动作头、动作块并行解码或OpenVLA-OFT类方法作为第二阶段升级，不阻塞首个完整闭环。

## 5. 多后端而不是“一把机械臂包办全部任务”

第五章15类任务包含物理操作、智能设备控制、监测、提醒和场景编排，统一采用Skill IR，按动作性质路由：

1. 刚性操作后端：抓取、轻放、推入、搬运、递送、柜门/抽屉操作；RoboCasa/OpenVLA。
2. 表面清洁后端：擦拭、拖洗和覆盖路径；评测覆盖率、接触力、残留率和碰撞。
3. 柔性物体后端：衣物、毛巾、床单、窗帘、塑料袋；使用柔性仿真、关键点/轮廓状态与双臂扩展。
4. 移动服务后端：跨房间取送、巡检和递送；导航与机械臂技能组合。
5. 智能家居/数字孪生后端：家电、环境、能源、场景联动和娱乐控制；以设备状态变化验证成功。
6. 监测告警后端：安防、健康和设施状态；以事件检测、告警路由和响应闭环验证成功。

只有物理操作后端输出机械臂动作参数。设备控制和监测任务输出结构化设备/API动作；强行转换成7维机械臂动作会违背任务本身。

## 6. 数据与训练职责

### 6.1 人类视频数据训练什么

- 人体/手部姿态与轨迹。
- 手—物接触和物体状态变化。
- 动作分段与15原语识别。
- `(Action, Object, Goal)` 意图和任务语法图。
- 对象中心的关键位姿与约束。

### 6.2 机器人示教数据训练什么

- 当前视觉与语言/技能阶段到机器人动作的映射。
- 抓取、接触、放置、恢复等闭环策略。
- 动作尺度、机器人坐标系、夹爪和动力学特性。

BridgeData V2/Open X-Embodiment用于OpenVLA预训练先验；RoboCasa专家、遥操作、IK重定向和DAgger数据用于目标场景适配。人类视频与机器人示教通过同一Skill IR关联，不假定两者逐帧一一对应。

### 6.3 训练顺序

1. 预训练感知模块直接复用并做领域适配。
2. 训练/校准15原语动作解析器和Skill IR生成器。
3. 采集仿真专家和重定向机器人成功示教。
4. OpenVLA LoRA/BC按对象族、任务阶段和后端训练。
5. 用DAgger补充当前策略真实访问的偏离状态与恢复动作。
6. 对奖励清晰且需持续优化的任务，再使用SAC等强化学习精调。
7. 实机阶段采用系统辨识、视觉/物理领域随机化、人类监督部署和少量真实数据微调。

## 7. 注册表与数据契约

实施阶段生成以下权威清单：

1. `service_task_registry.json`：第五章15类服务任务。
2. `dataset_task_registry.json`：Excel 15个数据集任务组及行源。
3. `action_primitive_registry.json`：15个核心原语及扩展原语。

## 8. 验收标准

### 8.1 15类服务任务

每类至少有一个代表性技能满足：

1. 有真实或公开的人类示范视频。
2. 自动生成通过Schema校验的Skill IR，不能手工填写完整序列冒充解析。
3. 具有明确后端、状态、动作、成功谓词和失败原因。
4. 根据当前视觉/设备反馈闭环执行，不播放与场景无关的固定轨迹。
5. 5个独立仿真/数字孪生种子中成功率不低于80%。
6. 保存从源视频、解析、训练数据、策略动作、监督器干预到结果的完整证据。

物理机器人部署前，仿真结果只能标记为“仿真验收通过”，不能写成实机完成。

### 8.2 123个候选对象与至少120个有效对象

- 全部123个候选对象进入对象注册表和任务适用矩阵，但不在映射前自动认定为全部有效。
- 每个任务—物体组合必须标记适用状态、理由、动作原语、执行后端和成功谓词。
- 只有在至少一个合理任务中完成闭环技能验证的对象才计入有效物体数。
- 若有效候选物体少于120个，从第五章补充对象并采用相同验收流程，直至有效物体不少于120个。
- 每个验收对象进行3次独立试验，至少2次成功。
- 对同一对象跨多个任务的复用只计一个物体，但分别记录技能结果。
- 对无法在当前物理后端操作的固定设施或传感器，使用设备状态/数字孪生闭环，不伪造机械臂抓取结果。

### 8.3 视频解析和策略指标

- 目标对象识别/跟踪成功率。
- 15原语宏平均F1与动作边界误差。
- 手—物接触事件F1。
- 意图三元组准确率。
- Skill IR Schema通过率必须为100%。
- 每类任务成功率、平均步数、恢复率和安全干预率。
- 学习策略原始动作占比与专家覆盖占比必须分别报告。
- 未见操作者、未见场景和未见物体分别评测，不能只报告训练种子。

## 10. 分阶段交付

### 阶段A：权威注册表与校验器

- 从Excel自动生成15个数据集任务组、123对象和138条源关系。
- 人工审核第五章15类服务任务及双层映射。
- 固化15原语、Skill IR Schema、成功谓词和证据目录。

### 阶段B：首条完整视频技能迁移

- 输入“人拿水杯并放入柜子”的视频。
- 自动产生人体/手/物体轨迹、动作阶段、意图三元组和Skill IR。
- Skill IR驱动现有RoboCasa/OpenVLA后端。
- seed 0和held-out seed 2形成源视频到机器人结果的端到端证据。

### 阶段C：15原语与刚性对象族

- 先完成握取、轻放、推入、搬运、旋转、递送等当前硬件可执行原语。
- 扩展杯、瓶、碗、盘、遥控器、书、钥匙等刚性对象族。
- 建立对象中心表示、阶段条件训练和批量DAgger评测。

### 阶段D：六类执行后端样板

- 刚性操作、表面清洁、柔性物体、移动服务、智能家居、监测告警各完成至少一个端到端样板。
- 用共享Skill IR和任务图组合覆盖第五章15类任务。

### 阶段E：候选123对象与有效120+对象规模化
