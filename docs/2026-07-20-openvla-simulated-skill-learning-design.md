# OpenVLA 模拟技能学习：项目实施设计

## 1. 目标与范围

本项目主路线采用视觉—语言—动作（Vision-Language-Action, VLA）方法：在 RoboCasa/MuJoCo 模拟家庭场景中，使用模拟机械臂相机画面和自然语言任务指令，预测连续机械臂动作，并在模拟器中验收任务是否完成。

不以人类视频为必需输入，不接入真实机械臂，不控制真实家电。已有 EPIC-KITCHENS 人类视频、姿态解析和动作映射保留为后续“人类示范技能提取”扩展，不纳入本阶段 OpenVLA 成功率。

## 2. 方法依据

OpenVLA 是公开的 7B 视觉—语言—动作模型，输入机器人视觉观测和语言指令，输出可直接解码为连续机器人动作的动作标记。其训练基础是机器人操作轨迹，因此本项目必须构造或复用模拟机器人轨迹，而不能用人类视频直接充当机械臂动作标签。

本项目复用 OpenVLA 的代码、模型结构、检查点和参数高效适配方法；不照搬其官方实验结果。

## 3. 系统结构

```text
15 类家庭任务、123 个物体、138 条任务—物体操作关系
                  ↓
RoboCasa/MuJoCo 模拟任务定义与语言指令
                  ↓
模拟机械臂相机画面 + 机器人状态 + 标准/示范动作轨迹
                  ↓
OpenVLA（推理或参数高效微调）
                  ↓
连续机械臂动作：末端位姿变化、夹爪开合等
                  ↓
模拟环境执行
                  ↓
任务成功、动作合法、指令跟随、失败原因报告
```

## 4. 数据与职责

| 数据/资产 | 用途 |
|---|---|
| 138 条任务—物体—操作关系 | 生成任务定义、标准指令、目标对象与验收条件 |
| `datasets/midterm_15task_delivery/` 的物体图片与标注 | 支持场景物体类别选择和视觉证据整理，不直接作为机械臂动作真值 |
| RoboCasa/MuJoCo 环境 | 生成机器人相机图像、状态、动作和任务成功标签 |
| OpenVLA 公开代码/检查点 | 将模拟图像和指令转为连续动作的 VLA 策略候选 |
| EPIC-KITCHENS 人类视频 | 可选的高层技能语义扩展；不作为本阶段 VLA 动作监督 |

## 5. 分阶段实现

### 阶段 A：模拟数据契约与基线任务

先选取本机可运行的少量代表性任务，例如抓取放置、物品递送、桌面擦拭或容器操作。每条模拟轨迹必须保存：

- 任务 ID、目标物体、中文/英文指令；
- 每时刻的相机图像或图像引用；
- 机械臂状态及连续动作；
- 动作空间定义、控制频率；
- 仿真成功标签、失败原因和随机种子。

### 阶段 B：OpenVLA 环境检查与动作适配

在下载大模型前检查本机 GPU、显存、磁盘、Python 依赖和模拟器动作空间。建立动作适配器，将 OpenVLA 输出转换为当前模拟器声明的动作范围，严格检查维度、缩放和夹爪约定。

### 阶段 C：模拟推理或参数高效适配

优先在一条或少量模拟轨迹上完成 OpenVLA 推理烟雾测试。只有环境、模型和动作空间均已验证后，才考虑基于模拟机器人轨迹进行 LoRA 等参数高效适配；不进行全参数重训。

### 阶段 D：模拟验收

对冻结的任务集进行多次独立随机种子回放，记录：

1. **任务成功率**：模拟环境达到任务成功条件的回合数 / 总回合数；
2. **动作合法率**：输出动作维度、范围、夹爪值和控制频率均符合模拟器要求的比例；
3. **指令跟随准确率**：模型执行的目标对象和操作与冻结任务定义一致的比例；
4. **失败可追溯性**：每次失败保留场景、指令、动作序列和模拟器原因。

## 6. 真实性边界

- “模拟任务成功”只代表 RoboCasa/MuJoCo 中的任务完成；
- 不代表真实机械臂已执行，也不代表真实家庭环境成功；
- 没有本机运行记录时，不报告 OpenVLA 成功率；
- 若模拟器 DLL、模型依赖、权重、显存或动作适配不满足，明确报告为未接入或未完成，不用符号化动作序列替代 OpenVLA 成功结果。
